# Build and Packaging

Every plugin is a single-module Gradle Kotlin build with the same three plugins:
`kotlin("jvm")`, `com.gradleup.shadow`, `xyz.jpenilla.run-paper` (a fork with Java 16
support) and `net.minecrell.plugin-yml.bukkit`.

## The version catalog is shared

`libs/` is a git submodule holding the `libs.versions.toml` every plugin in the family
shares, symlinked into `gradle/` so Gradle finds it. Dependencies are referenced as
`libs.wutilsConfig`, `libs.lootPool`, `libs.infPoints` — never as a literal coordinate — and
bumping a version means committing in the submodule, not editing one plugin. Clone with
`--recurse-submodules`, or run `git submodule update --init` afterwards.

Full setup, update workflow and troubleshooting: [The Shared Version
Catalog](version-catalog.md).

Company artifacts (`org.bigcraft:LootPool-api`, `InfPoints-api`, `ConnectionSource-api`,
`CustomItems-api`, `Storm-api`) come from the `mymavenrepo.com` repository configured in
`settings.gradle.kts`; the GitLab Maven repo needs a `gitLabPrivateToken` Gradle property.

## Scopes

- `compileOnly` — everything present at runtime on the server: Paper API, PlaceholderAPI,
  CommandAPI, WorldEdit/WorldGuard, InvUI, AbstractMenus, and **every `org.bigcraft` API
  artifact**. Infrastructure APIs are always `compileOnly`; the provider plugin supplies the
  classes.

  **InvUI is one of these.** The server runs a standalone `InvUi` plugin that bundles InvUI
  1.49, so take `libs.invUi` (and `libs.invUiKotlin`) as `compileOnly` with `InvUi` in
  `softDepend` — do not shade InvUI into your jar. Shading it duplicates a ~1 MB library per
  plugin and puts a second copy of its classes on the server; keep the catalog pin matching
  the version the server plugin ships.
- `implementation` — everything shaded into the jar: Guice, Adventure, EnhancedLegacyText,
  and the WUtils modules.

Add only the WUtils modules the plugin actually uses. The common baseline is
`wutilsConfig`, `wutilsConfigurables`, `wutilsI18nKotlin`, `wutilsCommonKotlin`; add
`wutilsJson` for JSON state, `wutilsStructure`/`wutilsAnimation` for world content.

## Shading

`shadowJar` sets `minimize()` and relocates every shaded package under
`org.bigcraft.<plugin>.shadow.…`, guarded by a `debug` property so a debug build keeps the
original names:

```kotlin
relocate("com.google.inject", "org.bigcraft.dungeons.shadow.google.guice")
relocate("net.kyori", "org.bigcraft.dungeons.shadow.net.kyori")
relocate("me.wyne.wutils", "org.bigcraft.dungeons.shadow.wutils")
```

When starting from the template, replace the `org.bigcraft.plugin` placeholder in every
relocate line — leaving two plugins sharing a shadow package is a real conflict.

## plugin.yml

Generated by the `bukkit { }` block; there is no `src/main/resources/plugin.yml`.

- `depend` for infrastructure a plugin cannot work without (`ConnectionSource`, `InfPoints`,
  `LootPool`, `WorldEdit`, `WorldGuard`).
- `softDepend` for everything an `OptionalModule` probes for (`PlaceholderAPI`, `CommandAPI`,
  `AbstractMenus`, `ProtocolLib`, `InvUi`, `DecentHolograms`).
- Permissions are declared here, with a `<plugin>.*` parent listing its children and one
  `register` block per node — matching the `withPermission` calls in
  [Commands](commands.md). Player-facing nodes get `default = Default.TRUE`; admin nodes
  stay OP-only.
- `name`, `version`, `website` and `author` come from `gradle.properties`; `apiVersion` is
  `1.16`.

## Running a test server

`./gradlew runServer` downloads LuckPerms, PlaceholderAPI, ProtocolLib, ViaVersion and the
forked CommandAPI, uses `run-template/` as the server template and `run-<version>/` as the
run directory. It targets 1.16.5 on Linux and 1.19.4 on Windows or with `-Pdebug=true`, and
runs on a JetBrains JDK 21 launcher with enhanced class redefinition enabled.
